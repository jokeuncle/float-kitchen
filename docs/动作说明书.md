# 看懂后厨

厨房将本地客户端明确暴露的活动映射为八种动作。厨师的姿势和画在姿势里的道具会随活动变化，配合整幅角色的运动与少量烟雾、光圈效果；工位牌直接显示客户端、活动及文件名或工具名。

| AI 活动 | 画面中看什么 | 信息与识别条件 |
|---|---|---|
| 读取文件 | 厨师捧着打开的食谱，厨师专注地轻轻摆动 | 识别 Read/read_file/list/graph 等；小票可显示文件名 |
| 搜索资料 | 厨师提着食材袋，提着采购袋回到工位 | 识别 search/web/browse 等检索工具 |
| 执行与修改 | 厨师翻锅，食材扬起，锅与身体一起发力 | 执行、编辑及通用工具调用；通用脚本不一定能细分 |
| 运行检查 | 厨师掀盖看锅，角色与锅具一起轻轻颤动 | test 工具，或可识别的 swift test/pytest/Checks 等命令 |
| 等待确认 | 厨师指向服务铃，身体轻摆并亮起提示光圈 | 只有显式 approval/request_user_input/waiting 事件可触发 |
| 操作失败 | 厨师担心地端着糊锅，工位冒黑烟 | 显式工具错误、已识别的非零退出码、failed 事件；沉默不算失败 |
| 本轮完成 | 厨师双手端盘，把餐盘送到柜台前 | Codex完成事件、Claude end_turn 或 served；不表示独立验证了任务质量 |
| 暂无活动 | 厨师端着咖啡休息 | 启动尚无事件，或两分钟没有新事件；不表示任务必然结束 |

应用右下角与菜单栏都有「看懂后厨」。点击某行的「看此动作」，厨房会切到明确标注的演示模式并单独展示该动作。点击「看场好戏」恢复连续演示，点击「真实活动」恢复本地监听。

三个工位从左到右代表 Codex、Claude、自定义事件。同一客户端的多个会话汇总到一个厨师。活动可能很快切换；纸质「订单小票」保留最近六步，便于回看。

演示数据均为虚构。真实事件使用来源时间，只处理近期活动；不显示对话内容、私有推理、工具输出、完整文件路径或命令参数。自定义客户端可以主动提供90字以内的任务说明 label。日志格式变化或不可识别的调用会造成信息缺失，此时以工具名和通用执行动作呈现。

动画遵循系统「减弱动态效果」。隐藏、被完全遮挡或休眠会停止连续动画；静态姿势、道具和工位牌仍表达状态。

工位牌保持静止，客户端/活动与详情分为两行，长文字按实际字体宽度显示省略号。姿势切换用360ms淡入淡出和280ms收势衔接，不会重启其他未变化的厨师。

## 常见语言的测试识别

解析实际执行的命令与专用 test 工具，支持绝对路径、环境变量、常见命令包装器、shell -c 及复合命令。不会因为日志文字中出现 test 就判为运行测试。

| 语言/生态 | 已纳入回归的运行方式 |
|---|---|
| JavaScript / TypeScript | node --test、npm/pnpm/yarn test、test:* scripts、npx/exec、Jest、Vitest、Mocha、Playwright、Cypress、Bun、Deno |
| Python | pytest、python -m unittest、uv/poetry/pipenv包装、coverage run -m pytest、tox/nox |
| Go / Rust | go test、cargo test、cargo nextest run |
| Swift / Apple | swift test、明确的 Swift Checks 入口、xcodebuild test |
| Java / Kotlin / Scala | Maven test/verify、Gradle test/check/Android test任务、JUnit/TestNG入口、sbt test |
| .NET | dotnet test / vstest |
| C / C++ | CTest、Make/Ninja test/check、CMake test target、Meson test、带gtest参数的测试程序 |
| Ruby / PHP | RSpec、Rake test/spec、明确的Ruby测试文件、PHPUnit、Pest、Artisan test |
| 其他 | Elixir mix test、Dart/Flutter test、Perl prove、R testthat、Julia Pkg.test、Clojure test别名、Bazel test |

这是明确列出的识别范围，不是任意脚本的语义分析器。自定义别名、由脚本深层动态拼出的测试命令或自定义可执行文件，可能显示通用「执行与修改」；客户端可以直接发 testing 事件消除歧义。安装测试框架、echo一段测试命令、读取test文件等不会冒充运行测试。
